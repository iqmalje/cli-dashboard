## Task 1: `hooks/look.ts`, the pure look model

Create `hooks/look.ts` and `hooks/look.test.ts`. Pure module, no engine calls. Nothing else changes in this

`hooks/look.ts`, written as below:

```ts
import { oklch } from './color'

// Each setting's values, default first; the plugin.json pickers and the setup wizard list them in this order.
export const CHOICES = {
  theme: ['pastel', 'rainbow', 'mono', 'light', 'high-contrast'],
  icons: ['nerd', 'plain'],
  animation: ['full', 'calm', 'off'],
  speed: ['1x', '0.5x', '2x'],
} as const

export type Choices = typeof CHOICES
export type Picks = { [K in keyof Choices]: Choices[K][number] }

const THEMES: Record<Picks['theme'], { color: (h: number) => string; border: string; track: string }> = {
  pastel: { color: h => oklch(0.85, 0.07, h), border: oklch(0.6, 0.05, 280), track: oklch(0.32, 0.02, 280) },
  rainbow: { color: h => oklch(0.75, 0.16, h), border: oklch(0.65, 0.12, 280), track: oklch(0.32, 0.02, 280) },
  mono: { color: () => oklch(0.85, 0.05, 250), border: oklch(0.6, 0.03, 250), track: oklch(0.32, 0.02, 250) },
  light: { color: h => oklch(0.5, 0.12, h), border: oklch(0.55, 0.05, 280), track: oklch(0.88, 0.01, 280) },
  'high-contrast': { color: h => oklch(0.9, 0.18, h), border: oklch(0.95, 0, 0), track: oklch(0.2, 0, 0) },
}

const NERD = {
  dir: '\u{F07B}',
  session: '\u{F0369}',
  branch: '\u{E0A0}',
  model: '\u{F06A9}',
  h5: '\u{F13AB}',
  d7: '\u{F00ED}',
  tokens: '\u{F01BC}',
  cache: '\u{F051B}',
  agents: '\u{F070E}',
  workflow: '\u{F0E43}',
  tasks: '\u{F012C}',
  skills: '\u{F0AD}',
}
export type Icons = typeof NERD

// single-width Unicode for terminals without a Nerd Font; no emoji, their width breaks cell alignment
const PLAIN: Icons = {
  dir: '▤',
  session: '@',
  branch: '⎇',
  model: '◆',
  h5: '◷',
  d7: '▦',
  tokens: '∑',
  cache: '↻',
  agents: '»',
  workflow: '⇶',
  tasks: '▣',
  skills: '✱',
}

// one icon per Dumb State, in STATES order (Smart, Coasting, Foggy, Cooked, Dumb)
const STATE_ICONS: Record<Picks['icons'], readonly string[]> = {
  nerd: ['\u{F09D1}', '\u{F015F}', '\u{F0591}', '\u{F0238}', '\u{F068C}'],
  plain: ['★', '◆', '≈', '▲', '✕'],
}

const SPEED: Record<Picks['speed'], number> = { '0.5x': 0.5, '1x': 1, '2x': 2 }

export type Look = {
  color: (h: number) => string
  border: string
  track: string
  icon: Icons
  states: readonly string[]
  // gradient shift and hue degrees per frame; 0 freezes them
  flow: number
  hue: number
  // false: running agents show a static ● and the frame tick is not started
  spin: boolean
}

// a value outside a setting's choices (unset, mistyped) means its default
export const picksFrom = (o: Readonly<Record<string, unknown>>): Picks => {
  const one = <K extends keyof Choices>(k: K): Picks[K] => {
    const list: readonly string[] = CHOICES[k]
    return (list.includes(o[k] as string) ? o[k] : CHOICES[k][0]) as Picks[K]
  }
  return { theme: one('theme'), icons: one('icons'), animation: one('animation'), speed: one('speed') }
}

export const lookOf = (p: Picks): Look => {
  const moving = p.animation === 'full'
  const s = SPEED[p.speed]
  return {
    ...THEMES[p.theme],
    icon: p.icons === 'plain' ? PLAIN : NERD,
    states: STATE_ICONS[p.icons],
    flow: moving ? 0.125 * s : 0,
    hue: moving ? 6 * s : 0,
    spin: p.animation !== 'off',
  }
}
```

`hooks/look.test.ts` covers, at least:

- `picksFrom({})` is `{ theme: 'pastel', icons: 'nerd', animation: 'full', speed: '1x' }`.
- `picksFrom({ theme: 'neon', icons: 'plain' })` keeps `icons: 'plain'` and falls back to `theme: 'pastel'`.
- The default look reproduces today: `lookOf(picksFrom({})).color(20) === pastel(20)` (import `pastel` from
  `./color`), `border === oklch(0.6, 0.05, 280)`, `track === oklch(0.32, 0.02, 280)`, `flow === 0.125`,
  `hue === 6`, `spin === true`.
- `speed: '2x'` gives `flow 0.25, hue 12`; `'0.5x'` gives `0.0625, 3`.
- `animation: 'calm'` gives `flow 0, hue 0, spin true`; `'off'` gives `flow 0, hue 0, spin false`.
- `mono`'s `color(10) === color(200)`.
- Every icon set has the same keys as NERD, and every `plain` icon and plain state icon has `width(...) === 1`
  (import `width` from `./format`).

## Task 2: draw with a Look, and the settings

Thread a `Look` through the drawing code so every colour, icon and motion comes from it, and expose the four
settings. After this task the settings work through `/config` and `claude plugin configure`.

1. `hooks/color.ts`: delete `pastel` only if nothing uses it after this task (tests may keep importing it; if
   they do, keep it). Change `flow(k, n, f)` to `flow(k, n, shift)`, where the caller passes the already
   scaled shift (`f * look.flow`): `const t = (((k / Math.max(1, n) - shift) % 1) + 1) % 1`. Update any test
   of `flow`.
2. `hooks/meter.ts`: drop `icon` from `STATES` (icons now come from `look.states`, indexed by the state's
   position in `STATES`). Keep `name` and `hue`.
3. `hooks/rows.ts`: delete `ICON` (moved to `look.ts`). `fixedRows`, `agentSections`, `taskSection` and
   `skillsSection` take `look: Look` as their last parameter. Every `pastel(h)` becomes `look.color(h)`, the
   meter's empty part uses `look.track`, every `ICON.x` becomes `look.icon.x`, the meter's state icon is
   `look.states[STATES.indexOf(st)]`. `ic` keeps its one-space rule for the branch icon by comparing
   against `look.icon.branch`. Hue cycling `f * 6` becomes `f * look.hue` (agent names and the in-progress
   task `▸`). A running agent's spinner is `SPIN[...]` when `look.spin`, else `●` in the same colour.
4. `hooks/frame.ts`: delete `BORDER`. `draw(sections, W, f, look, caption?)`: borders use `look.border`,
   and gradients call `look.color(a + (b - a) * flow(k, n, f * look.flow))`. Thread `look` to `cellSegs`.
5. `hooks/register.tsx`: `const look = lookOf(picksFrom(options))` in `register`, passed to every call above
   and to the caption (`look.icon.skills`). Start the 120ms frame tick only when `look.spin`.
6. `.claude-plugin/plugin.json` `userConfig`: add four `string` fields after `softLimit`, each with
   `options` (the `CHOICES` list, same order) and `default` (its first value), `required: false`, and a
   `title`/`description` in the style of `softLimit`. Theme description must call `pastel` recommended.
7. `tools/screenshots/render.ts`: pass `lookOf(picksFrom({}))`; replace `ICON` with `look.icon`. It must
   type-check; do not run it (needs Chrome and macOS paths).
8. Tests: update call sites in `rows.test.ts`, `frame.test.ts`, `meter.test.ts`, `register.test.tsx` to the
   new signatures with the default look. Add tests: a `mono` look draws the meter's state name in the same
   colour as the dir icon; `plain` icons put `look.icon.dir` in the first Fixed Row; `animation: 'off'`

## Task 3: the setup wizard

`/cli-dashboard-setup` opens a focused pane that asks the four questions one at a time with a live preview,
saves on the final enter, and a first-run hint points to it.

1. Register the command in `session.start` next to `cli-dashboard-skills`:
   `{ name: 'cli-dashboard-setup', description: 'Pick the cli-dashboard theme, icons and animation' }`.
   Its `command.run` hook opens the pane: `$.ui.open({ id: 'setup', title: 'cli-dashboard setup',
   focus: true, closeOnEscape: true, rows: <enough for question + preview> })` (see `examples/pane.tsx`
   and the `ui.open` doc in the types). It returns `{ text }` with one short line.
2. Session values (atoms in `register.tsx`, declared in `types/index.d.ts` `PluginState` like the
   existing ones): `setup: { step: number; picks: Picks } | null` (the wizard draft) and
   `chosen: Picks | null` (picks saved in this session; overrides `options` until the module reloads).
   The command sets `setup` to `{ step: 0, picks: <current picks> }`.
3. The effective look everywhere in `register.tsx` is `lookOf(chosen ?? picksFrom(options))`, read at
   draw time, replacing Task 2's fixed `look`. The frame tick must run while the wizard is open (its
   preview animates) or while the effective look spins; stop it otherwise.
4. The pane's `ui.render` hook (`{ component: 'Pane', requestId: 'setup' }`) draws:
   - a question line: the setting name, `◂ value ▸`, `(recommended)` after `pastel`, the step as `2/4`, and
     the keys `←/→ change · enter next · esc cancel`;
   - under it, the preview: `draw(...)` of `fixedRows` with the session's real data plus sample Activity
     Sections (a running agent, a finished agent, an in-progress task), with `lookOf(setup.picks)`. Put the
     sample `AgentRow[]` and `Task[]` in `hooks/sample.ts` and have `tools/screenshots/render.ts` import them
     from there instead of keeping its own copy.
   ←/→ cycle the current setting's `CHOICES` (wrapping); enter advances; the step for `speed` is skipped
   when `animation` is `off`. Use the pane's key handling as the types document it (a focused pane with
   `Button`s, or a `Client` with `onKey`; Escape is the pane's `closeOnEscape`).
5. Enter on the last step: set `chosen` to the picks, clear `setup`, close the pane, mark the hint done, and
   save: run `claude plugin configure <id> --values-stdin` through `$.process.run` with `stdin` the JSON
   `{ theme, icons, animation, speed }`. `<id>` is the `enabledPlugins` key that starts with
   `cli-dashboard@` (fall back to `cli-dashboard`). On a failed save, show `$.ui.toast` with one line saying
   the picks apply to this session only; never throw.
6. Esc (the pane closing by any route while `setup` is set): clear `setup`, save nothing, mark the hint
   done.
7. First-run hint: while `$.store` key `setupSeen` is unset, the Panel's bottom-border caption also shows
   ` ◆ /cli-dashboard-setup ` after the skills caption (pressing it opens the wizard if the caption API

   store once at `session.start` into an atom; never read it while drawing.
8. Tests in `register.test.tsx`, in the existing style: the command opens the pane; → changes the preview's
   look; enter through all steps calls the configure process with the picks as JSON and the Panel then
   draws with them; `off` skips the speed step; closing the pane mid-way saves nothing and leaves the Panel
   unchanged; the hint shows until the wizard closes once.
9. `README.md`: a short "Setup" paragraph near Settings naming `/cli-dashboard-setup`, and add the command
   to the controls table.
